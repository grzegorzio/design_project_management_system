# Техническое задание

> Адаптировано из раздела 1.6 ВКР «Разработка автоматизированной информационной системы управления проектами дизайнерской компании» (Каращук Р.С., САФУ, 2026). Оригинал разработан по ГОСТ 34.602–2020 для платформы 1С:Предприятие 8.3; здесь приведён в общем виде, без привязки к конкретной платформе.

## Цель разработки

Централизованное управление задачами, файлами и коммуникациями дизайнерской компании, автоматизация согласования дизайн-макетов, учёт времени и ресурсов, прозрачность процессов для сотрудников и клиентов.

## Роли пользователей

| Роль | Основные действия в системе |
|---|---|
| Руководитель проекта | Создаёт проекты, этапы, задачи; контролирует сроки, бюджет, загрузку команды |
| Дизайнер | Загружает макеты с версионностью, выполняет задачи |
| Арт-директор | Проверяет качество, устанавливает статусы согласования макетов |
| Клиент | Ставит ТЗ, согласовывает макеты, видит статус проекта |
| Администратор | Управляет ролями и доступом |

## Бизнес-процесс TO-BE

1. Клиент оставляет заявку/ТЗ через систему
2. Руководитель создаёт проект, назначает команду
3. Дизайнер выполняет задачи, загружает версии макетов
4. Арт-директор проверяет и комментирует макет
5. Клиент согласовывает или отправляет на доработку
6. По завершении — формируется отчёт, финальные материалы передаются клиенту

Ключевые особенности TO-BE: централизованное управление, прозрачность для клиента, контроль сроков и загрузки, электронное согласование макетов.

## Функциональные требования (детально)

- Создание и ведение проектов, этапов и задач
- Поддержка версионности файлов и истории изменений
- Установка и отслеживание статусов согласования макетов
- Диаграмма Ганта и календарь задач
- Тайм-трекинг и контроль загрузки сотрудников
- Формирование аналитических отчётов
- Настройка ролей и прав доступа

## Требования к интерфейсу и интеграциям

- Интуитивно понятный интерфейс
- Экспорт/импорт данных (Excel, PDF)
- Интеграция с внешними сервисами хранения и коммуникации

## Нефункциональные требования

- **Надёжность** — устойчивая работа при многопользовательском доступе
- **Производительность** — быстрый отклик при работе с проектами и файлами
- **Масштабируемость** — рост числа проектов/сотрудников/клиентов без деградации
- **Безопасность** — разграничение прав доступа, контроль версий документов
- **Совместимость** — интеграция с облачными хранилищами и дизайн-инструментами (Figma, Adobe)

## План-график выполнения работ (оригинальный, 8 недель)

| Этап | Длительность |
|---|---|
| Анализ требований и проектирование архитектуры | 2 недели |
| Разработка структуры данных и модулей | 3–4 недели |
| Настройка интерфейсов и интеграций | 2 недели |
| Тестирование и корректировка | 1–2 недели |
| Внедрение и обучение сотрудников | 1 неделя |
